### 1.2 Module-Level Bottleneck Assessment
Based on telemetry data, the following bottlenecks were identified:

*   **CameraCapture (REQ-007):** The capture rate was limited to ~30 FPS due to a conservative `camera_fps` setting in `config.json` and disabled `FrameDurationLimits` in the source code.
*   **CsvLogger (REQ-001):** A synchronous disk flush occurred every 10 log entries in the hot path. This correlates with the observed 1200ms latency spikes, as the processing threads were blocked during I/O wait.
*   **InferenceEngine (REQ-001):** Single-threaded inference took ~19ms per frame. For 120 FPS target, the total budget per frame is 8.33ms. Parallelization is mandatory.
*   **ImageProcessor_Viz (REQ-001):** Visualization and NMS logic contributed ~10-15ms of latency. Sequential execution with inference exceeded the 100ms budget during load.

## 2. Corrective Actions Implemented

The following changes have been implemented to achieve compliance for Stage 2 Testing:

### 2.1 Latency Optimization (REQ-001)
*   **Async Logging:** Removed synchronous `flush_buffer_to_disk()` from `CsvLogger::write_entry`. Flushing is now handled exclusively by the background `log_flusher_thread` every 100ms.
*   **Inference Parallelization:** Increased `inference_worker_threads` to 4 in `config.json` and updated `InferenceEngine` to respect this setting (previously forced to 1).
*   **Hot Path Cleanup:** Removed `std::cerr` and non-critical `APP_LOG_INFO` statements from `InferenceEngine::worker_thread_func` and NMS logic to reduce string formatting overhead and I/O pressure.
*   **Budget Tightening:** Set `MAX_FRAME_BUDGET_RAW_MS` to 100ms in `src/logic.h` to ensure fail-closed behavior for any remaining outliers.

### 2.2 Throughput Optimization (REQ-007)
*   **Camera Configuration:** Updated `config.json` to set `camera_fps` to 120.0.
*   **Frame Duration Locking:** Enabled `libcamera::controls::FrameDurationLimits` in `src/camera_capture.cpp` to explicitly request 120 FPS from the IMX708 sensor.
