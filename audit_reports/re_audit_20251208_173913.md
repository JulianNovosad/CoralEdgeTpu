# Re-Audit Report - Mon Dec 08 17:39:13 UTC 2025

This report details the findings of an audit against the project's README.md specifications and codebase implementation.

## Audit Findings:

### 1. Dependencies Check (libzmq3-dev)
*   **README.md Specification:** `libzmq3-dev` is listed as a system prerequisite, and ZeroMQ PUB/SUB is described as a core functionality for telemetry.
*   **Codebase Implementation:** `build.sh` does not install `libzmq3-dev`, and `CMakeLists.txt` does not include any directives to find or link ZeroMQ libraries. A search for ZeroMQ-related terms in `src/` yielded no results.
*   **Discrepancy Level:** **Major**. ZeroMQ functionality is entirely absent from the build and implementation, despite being a stated core feature.

### 2. config.json Check
*   **README.md Specification:** A `config.json` file is expected in the repository root with a specific nested structure, including `video_stream` and `telemetry` objects with `protocol` and `address` fields, and a `network_ports` object.
*   **Codebase Implementation:**
    *   The `config.json` file is **missing** from the repository root.
    *   `ConfigLoader` (in `src/config_loader.cpp`) is designed to parse an `application` object, which is consistent with the README's example.
    *   However, `ConfigLoader`'s getters for network ports expect named properties (e.g., `livestream_video`) within `network_ports`, whereas the `README.md` example uses port numbers as keys.
    *   Crucially, `ConfigLoader` lacks explicit getters for the `protocol` and `address` fields of the `video_stream` and `telemetry` objects described in the `README.md`.
*   **Discrepancy Level:** **Critical (missing file) & Major (structural and missing getter discrepancies).** The application cannot load crucial streaming and telemetry configuration details as specified.

### 3. Architecture vs. README (Streaming/http_server.cpp)
*   **README.md Specification:**
    *   H.264 video encoding and real-time streaming via **UDP/RTP or RTSP**.
    *   Bounding boxes, reticle coordinates, and telemetry via **ZeroMQ PUB/SUB**.
*   **Codebase Implementation:**
    *   The current implementation in `src/http_server.cpp` uses **HTTP WebSockets with CivetWeb** for video streaming. This is a fundamentally different protocol.
    *   There is **no implementation** of UDP/RTP/RTSP for video streaming.
    *   There is **no implementation** of ZeroMQ for telemetry.
    *   A search in `src/` revealed `TODO` comments and documentation in `src/orientation_sensor.cpp` and `src/config_loader.h` indicating an *intent* to use UDP for orientation data, but no active implementation.
*   **Discrepancy Level:** **Major**. The implemented network architecture for streaming and telemetry directly contradicts the specifications in `README.md`.

### 4. Threading Model
*   **README.md Specification:** Stage 1 mentions a "mutex-gebaseerde ThreadSafeQueue".
*   **Codebase Implementation:** The project currently uses `boost::lockfree::spsc_queue` for inter-thread communication (`pipeline_structs.h`).
*   **Discrepancy Level:** **Minor**. While a discrepancy, the `boost::lockfree::spsc_queue` is generally a more performant choice for single-producer, single-consumer scenarios, suggesting an improvement over the README's description.

### 5. Dead Code
*   **README.md Specification:** Implicitly, no dead code should exist.
*   **Codebase Implementation:** All `.cpp` files found in the `src/` directory are explicitly included and compiled into the `detector` executable via `CMakeLists.txt`.
*   **Discrepancy Level:** **None**. The codebase is consistent with this implicit requirement.

### 6. Documentation
*   **README.md Specification:** Explicitly states the need for Dutch documentation, including comments.
*   **Codebase Implementation:**
    *   `src/logic.h` contains well-structured Doxygen-style comments primarily in **Dutch**.
    *   `src/main.cpp` and `src/util_logging.h` contain comments primarily in **English**.
*   **Discrepancy Level:** **Minor**. While some documentation is in Dutch, the language is inconsistent across the codebase.

## Summary of Critical Issues:
1.  **Missing config.json:** The application relies on this file, and it is absent.
2.  **ZeroMQ/RTP/RTSP/UDP Implementation Gap:** Core streaming and telemetry functionalities described in the README (using ZeroMQ/RTP/RTSP/UDP) are not implemented. The current system uses HTTP WebSockets instead.
3.  **Dependency Discrepancy (libzmq3-dev):** The required ZeroMQ library is not installed or linked.
4.  **ConfigLoader Mismatch:** The `ConfigLoader` cannot parse the `video_stream` and `telemetry` objects as defined in the `README.md`, and the `network_ports` structure differs.
